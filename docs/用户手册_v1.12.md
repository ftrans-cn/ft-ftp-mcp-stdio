# FT Agent FTP 插件用户手册 v1.12

> 适用产品版本：`ft-ftp-mcp-stdio 0.3.0`（Windows x64、Python 3.12）

## 接入

本服务通过 stdio 运行，正式支持 Codex 和 WorkBuddy。客户端启动命令指向已安装虚拟环境的 Python，并使用 `-m ft_ftp_mcp_stdio`；`stdout` 只承载 JSON-RPC。

首次使用运行 `ft-ftp-mcp-stdio setup` 创建配置 v2，再使用 `cred add <alias>` 把密码或私钥口令保存到系统凭据管理器。setup 不迁移或覆盖其他配置版本。

## 安全默认值

- 每台服务器必须配置真实 `root`，但 Agent 只看到虚拟 `/`。
- `readOnly` 默认 `true`；需要上传、建目录、移动或删除时才显式改为 `false`。
- `description` 仅用于 `list_servers` 选择逻辑服务器，不应包含地址、账号、路径或密钥名。
- SFTP 在认证前校验配置指纹或 known-hosts/TOFU；首次连接可能写入本地信任状态。
- FTP 不加密网络传输，且无法可靠识别所有符号链接；敏感数据优先使用 SFTP。

## 工具使用

共 14 个工具。服务器不明确时先调用 `list_servers`。所有远程路径都是虚拟绝对路径，例如 `/reports/a.csv`；不要传真实服务器 root。

上传默认拒绝覆盖，并先写入同目录 `.目标名.ft-upload-<16hex>.tmp`，完整写入后提交。`overwrite=true` 只有在 driver 能确认安全原子替换时才允许。`max_file_size_bytes` 只限制单个上传文件，`0` 表示不限制。

批量工具的 `ok:true` 只表示工作流返回了结构化结果。必须检查 `status`、`failed`，上传还要检查 `indeterminate`。出现 `indeterminate` 或 `outcome_unknown` 时停止自动重试，由用户核验列出的对象。

下载写入随机 staging 目录。已知远端大小不匹配或可证明来源变化时，结果以 `integrity_check_failed` 失败并清理无效文件。

## 维护命令

```text
ft-ftp-mcp-stdio setup
ft-ftp-mcp-stdio doctor [--server alias]
ft-ftp-mcp-stdio cred add|list|remove <alias>
```

doctor 不写配置、凭据或 TOFU 状态；它会提示 `root=/` 和 description 疑似包含敏感连接信息等风险。

## 已知边界

本地上传没有允许根白名单；staging 没有 TTL 或配额；批量调用没有文件数量或总字节限制；SFTP 和本地链接检查仍有 TOCTOU；FTP 链接识别依赖服务器元数据。完整已接受风险见 Accepted Spec 第 19 节。
