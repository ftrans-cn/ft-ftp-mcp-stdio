# ADR 0004：拒绝通过符号链接访问远程对象

- 状态：Superseded
- 日期：2026-09-21
- 接受日期：2026-09-21
- 取代者：`docs/decisions/0006-reject-symbolic-link-access-across-supported-protocols.md`
- 关联 Spec：`docs/spec/changes/next-development.md`

## 背景

> 本记录已由 ADR 0006 取代。原始决定保留用于追溯，不再作为当前实施依据。

虚拟远程路径把每个逻辑服务器的配置 root 作为 Agent 可见边界。文件系统符号链接可能把 root 内的名称指向其他位置；即使目标仍在 root 内，解析和跟随链接也会增加路径判断、循环、断裂链接和检查后替换等复杂性。若目标位于 root 外，服务器账号自身拥有访问权限也不代表 MCP 获得了越过配置 root 的授权。

SFTP 通常可以通过 `lstat` 识别符号链接，但 FTP/FTPS 没有可靠、统一的逐段识别能力。服务器管理员显式配置的虚拟目录映射则是另一类对象，代表服务器命名空间和授权配置，不应与文件系统符号链接混为一谈。

## 候选方案

1. 解析符号链接，规范化目标后仅允许仍位于配置 root 内的目标。
2. 不解析或跟随任何符号链接，检测到链接即拒绝或在批量处理中跳过。
3. 完全信任服务器授权，像通用 FTP/SFTP 客户端一样跟随服务器允许访问的链接。

## 决定

采用方案 2。

- 产品不支持通过符号链接访问或操作文件和目录，不因目标可能位于配置 root 内而例外放行。
- SFTP 从配置 root 开始，对每个既有路径段执行不跟随最终链接的 `lstat`。发现链接后立即停止，不调用 `readlink`，也不以 `realpath` 解析后的目标作为授权依据。
- 配置 root 本身或到达 root 的可见路径段包含符号链接时，该服务器配置无效。
- 单对象工具的路径经过链接或最终对象是链接时，返回稳定错误 `symlink_unsupported`，不得读取、下载、覆盖、删除、重命名或移动链接本身。
- `list_dir` 可以把普通目录中的链接条目显示为 `type:symlink`，但不返回目标路径或目标属性。以链接作为待列目录时拒绝。
- `search_files` 不进入或返回链接；`download_dir` 和 `upload_dir` 将链接记入 `skipped` 并继续处理其他条目。
- SFTP 强制检查无法可靠完成时 fail-closed，不得降级执行原操作。
- FTP/FTPS 在服务器或驱动明确识别链接时执行同样的拒绝或跳过，但不承诺能够可靠识别所有底层链接。
- Serv-U Virtual Path 等管理员显式配置的服务器虚拟目录映射不属于符号链接，在服务器授权允许时按普通目录处理。

具体错误结构、批量结果和工具验收标准以关联 Spec 为准。

## 理由

- root 内目标通常可以通过正常虚拟路径直接访问，没有支持链接别名的必要。
- root 外目标不属于 MCP 配置授权范围，即使服务器账号能够访问也不应放行。
- 完全拒绝比解析后判定更容易审查、测试和向 Agent 解释。
- 不读取链接目标可以减少目标路径及服务器目录结构暴露。
- 明确区分文件系统链接和服务器虚拟目录，保留管理员通过服务器授权配置共享目录的能力。

## 后果

正面影响：

- SFTP 的路径授权规则保持单一，不需要判断链接目标是否仍在 root 内。
- Agent 可以获得稳定、不可重试的拒绝原因。
- 批量工具不会因单个链接放弃其他普通文件。

代价与风险：

- 用户不能通过便捷的符号链接别名访问 root 内对象，必须使用目标的正常虚拟路径。
- 用户不能通过 MCP 删除或整理符号链接本身，需要使用服务器管理工具处理。
- SFTP 的逐段检查增加协议往返，并仍存在检查与实际操作之间的 TOCTOU。
- FTP/FTPS 可能无法识别服务器底层符号链接，最终隔离仍依赖服务端虚拟根、chroot、目录访问规则和账号权限。

## 验证

- 覆盖 root、中间路径段、最终对象、断裂链接、链接循环和检查失败。
- 验证检测到链接后不调用 `readlink`、不读取目标属性，也不执行原业务操作。
- 验证 `list_dir` 只显示 `type:symlink`，单对象工具返回 `symlink_unsupported`。
- 验证搜索不进入链接，批量上传和下载逐项跳过并继续。
- 验证强制 SFTP 检查失败时 fail-closed。
- 验证服务器虚拟目录映射不会被误判为文件系统符号链接。
- 验证 FTP/FTPS 文档和测试不把启发式链接识别描述为可靠保证。

## 回滚

如需支持符号链接，必须通过新的 ADR 明确目标解析规则、root 内外判定、循环和断裂链接行为、读写操作差异、TOCTOU 缓解以及 FTP/FTPS 的协议不对称，并取代本决定。实现阶段的代码回退仍按执行清单记录的 Start SHA 执行，并同步恢复匹配的 Schema、测试和文档。
