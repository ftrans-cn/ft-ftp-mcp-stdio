# ADR 0006：在受支持协议和本地上传路径中拒绝符号链接

- 状态：Accepted
- 日期：2026-09-21
- 接受日期：2026-09-21
- 取代：`docs/decisions/0004-reject-symbolic-link-access.md`
- 关联 Spec：`docs/spec/changes/next-development.md`

## 背景

ADR 0004 已决定不解析或跟随符号链接，但错误地把尚未支持的 FTPS 写入规范范围，且没有完整定义本地上传路径中的符号链接、Windows junction/reparse point 和检查后替换。本项目当前只支持 FTP 与 SFTP；本地上传链接同样可能使进程读取上传根之外的文件。

## 候选方案

1. 保留 ADR 0004，仅在实现中自行解释 FTPS 和本地路径行为。
2. 保持拒绝符号链接的核心决定，明确协议范围为 FTP/SFTP，并把本地上传链接与 reparse point 纳入同一 fail-closed 策略。
3. 允许本地链接，仍只拒绝远端链接。

## 决定

采用方案 2，并取代 ADR 0004。

- 产品不支持通过远端或本地符号链接访问、下载、上传或操作对象，不因链接目标位于允许根内而例外。
- SFTP 从配置 root 开始逐段执行不跟随链接的检查；检测到链接即拒绝或在批量处理中跳过，不调用 `readlink`，也不把 `realpath` 结果作为授权依据。
- FTP 仅在服务器元数据或 driver 能明确识别链接时执行相同拒绝；不能可靠识别时不得宣称已完成链接隔离，安全边界依赖服务器配置。
- FTPS 不在当前协议枚举、实现或验收范围内。
- `upload_file` 和 `upload_dir` 检查本地上传根、中间路径段和最终文件，不得跟随符号链接、Windows junction 或其他 reparse point。
- 本地文件在枚举时和打开前检查，并在读取任何字节前通过打开后的句柄复核身份与类型；对象被替换或无法可靠检查时 fail-closed。
- 单对象工具检测到链接时返回 `symlink_unsupported`；批量根路径工具级拒绝，批量单项记入 `skipped` 后继续。
- Serv-U Virtual Path 等管理员配置的服务器虚拟目录映射不是文件系统符号链接，在服务器授权允许时按普通目录处理。

具体错误结构、FTP/SFTP 能力差异、批量状态和检查失败处理以关联 Spec 为准。

## 理由

- 远端和本地链接都能改变路径实际指向，应采用一致的最小能力策略。
- 显式排除 FTPS，避免未经设计扩大 TLS、证书信任和 live 验收范围。
- junction 与 reparse point 是 Windows 上与符号链接相同类别的路径重定向风险。
- fail-closed 比在能力不足时继续读取或写入更符合虚拟 root 和本地数据保护目标。

## 后果

正面影响：

- 支持协议、远端路径和本地上传路径的链接策略一致且可测试。
- Agent 不会因链接别名访问配置 root 或本地上传根之外的对象。
- 不会把未实现的 FTPS 隐含加入产品范围。

代价与风险：

- 用户不能通过链接别名操作本可直接访问的对象。
- SFTP 和本地路径检查增加系统调用或协议往返。
- FTP 可能无法识别底层链接。
- 逐段检查、打开前检查和句柄复核仍不能完全消除并发替换造成的 TOCTOU；可靠边界依赖服务器隔离、本机账号权限和受信任文件系统。

## 验证

- 远端覆盖 root、中间段、最终对象、断裂链接、链接循环和 SFTP 检查失败。
- 本地覆盖上传根、中间目录、最终文件、断裂链接、Windows junction/reparse point 和检查后替换。
- 验证检测到链接后不读取目标、不执行原业务操作且不披露目标路径。
- 验证 FTP 文档和测试不把启发式识别描述为可靠保证，且不存在 FTPS 契约或验收项。
- 验证服务器虚拟目录映射不被误判为文件系统符号链接。

## 回滚

如需支持任一类型的链接，必须通过新的 ADR 定义解析规则、授权边界、循环和断裂行为、TOCTOU 缓解及协议差异，并取代本决定。实现阶段的代码回退按执行清单记录的 Start SHA 执行。
