# ADR 0002：配置 v2 与默认只读策略

- 状态：Accepted
- 日期：2026-09-20
- 接受日期：2026-09-21
- 关联 Spec：`docs/spec/changes/next-development.md`

## 背景

当前配置允许省略 root，且 `readOnly` 缺省为 `false`。新用户如果没有显式理解这些字段，可能获得超出预期的远程路径范围或写能力。本轮还需要增加服务器 description，并改变路径和公开 MCP 契约；继续接受旧配置会使同一字段在不同版本下具有不同安全含义。

## 候选方案

1. 保持配置 v1，通过兼容默认值逐步迁移。
2. 引入配置 v2，仅接受新契约，要求 root，默认只读，不提供自动迁移。
3. 同时支持 v1 和 v2，并在运行时维护两套兼容语义。

## 决定

采用方案 2。

- 新配置使用 `version:2`，运行时只接受版本 2。
- root 为必填字段；显式 `/` 合法，但必须提示其服务端隔离依赖。
- `readOnly` 缺省为 `true`，只有显式配置 `false` 才允许写操作。
- setup 仅在不存在现有配置时直接创建 v2 配置。遇到其他版本时不得自动迁移或覆盖，必须提示用户先备份并显式删除或替换旧配置。
- 写操作的只读拒绝发生在凭据读取和远端连接之前。
- 服务器可以配置用于展示和选择的 description，但不得把它当作秘密存储位置。

字段细节、校验规则和错误契约以关联 Spec 为准。

## 理由

- 安全默认值应在用户没有额外操作时关闭远端写能力。
- root 必填使每个逻辑服务器的远程范围明确可审查。
- 单一配置版本避免长期维护两套路径、安全默认值和错误行为。
- 当前产品前提允许不为旧用户提供兼容迁移层。

## 后果

正面影响：

- 新配置默认遵循最小权限原则。
- 配置加载、setup、doctor 和文档可以围绕单一契约实现。
- 写操作门禁可以在连接前一致执行。

代价与风险：

- 现有 v1 配置会被明确拒绝；用户备份并显式删除或替换旧配置后，才能重新运行 setup 创建 v2 配置。
- 配置版本升级不提供自动迁移、自动恢复或回滚兼容能力。
- 本地上传路径白名单不属于本决定，进程仍可读取其权限范围内的绝对路径。

## 验证

- 验证 setup 生成 v2，其他版本被拒绝且不会被隐式转换。
- 验证 root 必填、`/` 风险提示、description 校验和默认只读展示。
- 验证所有写操作在凭据读取和连接建立前被默认只读策略拒绝。
- 更新共享测试夹具、CLI、doctor、配置 Schema、样例和经授权的 live 配置。

## 回滚

代码可通过独立提交回退到本轮 Start SHA，但已经生成或部署的 v2 配置不保证能由旧代码读取。实施和发布前必须明确备份现有配置；需要回退时恢复与旧代码匹配的配置备份，不能把重新解释 v2 字段当作可靠恢复方案。
