# ADR 0001：虚拟远程路径安全边界

- 状态：Accepted
- 日期：2026-09-20
- 接受日期：2026-09-21
- 关联 Spec：`docs/spec/changes/next-development.md`

## 背景

当前 MCP 工具会接收和返回真实服务器路径。这样既会向 Agent 暴露服务器目录结构，也会让工具调用方必须理解不同服务器的真实 root。仅依赖字符串前缀检查还容易在相似目录前缀、规范化和异常输出中产生边界错误。

本项目需要提供一致的 Agent 可见路径，同时承认 FTP/SFTP 客户端无法单独构成强安全隔离，特别是符号链接、服务端虚拟根和并发变化场景。

## 候选方案

1. 继续公开真实服务器绝对路径，仅加强前缀检查。
2. 为每个服务器提供以 `/` 开始的虚拟远程路径，由服务内部完成正向和反向映射。
3. 完全依赖服务端 chroot 或受限账号，不在客户端维护 root 边界。

## 决定

采用方案 2，并继续把服务端 chroot、虚拟根或受限账号视为可靠安全边界的重要组成部分。

- Agent 输入和输出中的远程路径只使用以 `/` 开始的虚拟远程路径；规范明确允许的本机路径字段保持各自语义。
- `/` 表示当前逻辑服务器配置的 root，真实 root 只在服务内部使用。
- 映射前后均执行边界校验，driver 返回值和异常在进入业务结果前完成反向映射或净化。
- 虚拟 `/` 不允许被删除、移动或重命名，也不能作为移动目标。
- 无法安全反向映射的真实路径不得原样返回。
- SFTP 在协议和实现能力允许时检查路径段及最终目标的符号链接语义，但客户端检查不宣称形成强隔离。
- 虚拟路径规则只约束远程路径。`upload_dir` 的批量明细使用相对于本次 `local_path` 的规范化本机源相对路径，不返回盘符、UNC 前缀、上传根目录本身或根目录之外的路径。

具体路径规则、错误语义和验收标准以关联 Spec 为准，本 ADR 不重复定义工具契约。

## 理由

- 对 Agent 隐藏真实服务器布局，减少连接和部署信息暴露。
- 为不同服务器提供一致路径模型，降低工具描述和调用复杂度。
- 将 root 映射集中在业务边界，便于对成功结果、批量明细和异常统一净化。
- 明确区分客户端防护与服务端强隔离，避免过度安全承诺。

## 后果

正面影响：

- 所有工具获得统一的远程路径语义。
- 真实 root 不再属于公开 MCP 契约。
- root 保护和敏感信息测试可以集中实施。

代价与风险：

- 现有路径处理、driver 返回值、错误文本、测试和文档需要整体调整。
- 批量上传明细需要稳定生成本机源相对路径，并拒绝任何无法证明位于本次上传根目录内的条目。
- FTP 通常不能可靠提供 canonical path 和符号链接语义。
- SFTP 检查仍可能受到 TOCTOU 影响。
- 配置 root 为 `/` 时，可靠隔离仍取决于服务端配置和账号权限。

## 验证

- 覆盖相似前缀、`.`、`..`、反斜杠、NUL、虚拟 `/` 和真实路径误传。
- 验证 driver 返回路径和携带真实 root 的异常不会泄露到 Agent 可见结果。
- 评估 Paramiko `lstat` 等能力，记录路径段、最终目标和检查失败时的策略及测试证据。
- 经授权在 FTP/SFTP live 环境验证虚拟路径与服务端 root 的映射。

## 后续裁决

ADR 0006 已将本决定中“协议和实现能力允许时检查”进一步收紧为当前强制规则：SFTP 必须从配置 root 开始逐段执行 `lstat`，发现符号链接即拒绝，无法可靠检查时 fail-closed；FTP 只在能够明确识别链接时拒绝，并明确保留协议能力边界。链接处理以 [ADR 0006](0006-reject-symbolic-link-access-across-supported-protocols.md) 和当前 Spec 为准。本节只说明后续决策关系，不改写本决定形成时的历史内容。

## 回滚

实现失败时通过独立提交回退到本轮 Start SHA 对应的真实路径实现，并恢复与该代码一致的 Schema、测试和文档。配置 v2 或其他不兼容数据一旦用于外部环境，不承诺仅靠代码回退自动恢复；必须在实施或发布前单独备份并验证恢复边界。
