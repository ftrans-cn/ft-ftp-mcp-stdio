# ADR 0007：以首次检查快照授权上传提交

- 状态：Accepted
- 日期：2026-09-21
- 接受日期：2026-09-21
- 关联 Spec：`docs/spec/changes/next-development.md`
- 取代：`docs/decisions/0005-safe-upload-commit.md`

## 背景

ADR 0005 要求上传先写入同目录临时对象，但没有完全裁决临时名称的独占创建以及 `overwrite=false` 的并发提交语义。独立复审建议：服务器不能证明支持原子独占创建和原子 no-replace 时一律拒绝上传。该方案能够提供最强的并发无覆盖保证，但 FTP/SFTP 缺少统一能力，可能使一部分常规服务器无法使用上传。

项目需要在兼容性和并发隔离之间明确选择，并保证 `overwrite=false` 的描述与实际可实现行为一致。

## 候选方案

1. 要求临时对象原子独占创建，并要求 `overwrite=false` 使用原子 no-replace；服务器能力未知或不支持时 fail-closed。
2. 以传输前首次目标检查作为授权快照，使用低成本随机临时名称和普通 rename；明确接受检查后的目标及临时名称竞态。
3. 直接写入最终目标，失败时尽力删除部分文件。

## 决定

采用方案 2，同时继续对 `overwrite=true` 使用更严格的原子替换能力门禁。

- `upload_file` 和 `upload_dir` 的每个文件均先写入最终目标同目录的临时对象。
- 临时名称格式为 `.<目标文件名>.ft-upload-<16 位小写十六进制>.tmp`；随机部分使用 `secrets.token_hex(8)` 或等价的密码学安全 64 位随机源。
- 创建临时对象前检查该名称是否存在；冲突时重新生成，最多尝试 3 次，3 次均冲突时返回 `server_error`。检查通过后不要求协议级原子独占创建，也不执行第二次名称检查。
- `overwrite=false` 只在每个文件开始上传前检查一次最终目标。目标当时存在即返回 `policy_rejected`；目标当时不存在即授权本次调用在完整上传后执行普通 rename，不在提交前二次检查，也不要求服务器支持原子 no-replace。
- 首次检查后其他来源创建或替换同名最终目标，不视为本次调用违反 `overwrite=false`。若服务器明确拒绝 rename，不得删除目标或强制替换；能够确定为目标冲突时返回 `policy_rejected`，否则返回 `server_error`。
- `overwrite=true` 只有在 driver 能确认服务器支持不预先删除旧目标的安全原子替换时才允许；能力未知或不支持时返回 `policy_rejected`。禁止“先删除旧目标，再 rename”的降级路径。
- 只有完整写入、未超限、远端句柄成功关闭且必要校验通过后才允许提交。提交请求发出后响应丢失时不得重放，返回 `outcome_unknown`。
- 失败、取消或超限时只清理本次调用生成的确切临时路径；临时名称不返回给 Agent，不扫描或删除归属不明对象。

## 理由

- 单一检查点让 `overwrite=false` 成为清晰、可实现的调用授权条件，不把它描述为跨协议事务保证。
- 64 位随机名称和最多 3 次初始冲突重试，在保持低实现与协议开销的同时，使非恶意碰撞概率足够低。
- FTP/SFTP 服务器无需提供并不普遍的原子独占创建和原子 no-replace，降低早期用户因服务器能力差异无法上传的摩擦。
- `overwrite=true` 仍保护调用开始前已经存在的数据，不以兼容性为由接受先删除旧目标的高风险降级。

## 后果与残余风险

正面影响：

- 支持普通 rename 但不支持原子 no-replace 的服务器仍可执行 `overwrite=false` 上传。
- 超限、取消或传输失败通常只影响临时对象，不直接暴露部分最终文件。
- 工具参数的语义与可测试检查点一致。

代价与风险：

- `overwrite=false` 不保证首次检查后新出现的同名目标不被普通 rename 覆盖；服务器也可能选择拒绝 rename。
- 临时名称检查与实际创建之间存在竞态；另一写入者可能抢占或替换该临时路径。64 位随机值降低偶发碰撞，但不构成原子所有权证明。
- 如果服务端或攻击者能观察并主动抢占临时名称，可能影响本次上传或其清理结果。
- 项目负责人于 2026-09-21 明确接受上述竞态，以换取更广的 FTP/SFTP 服务器兼容性。

## 验证

- 分别覆盖 FTP、SFTP、`upload_file` 和 `upload_dir`。
- 验证临时名称格式、64 位随机源、初始冲突重试 1 至 3 次以及第 3 次后失败。
- 验证只检查并清理本次生成的确切临时路径，且不会向 Agent 返回该名称。
- 验证 `overwrite=false` 在首次检查时目标存在即拒绝，目标不存在即继续，提交前不执行第二次存在性检查。
- 注入首次检查后目标被创建或替换的场景，验证普通 rename 的服务器实际结果被如实处理；服务器明确拒绝目标冲突时返回 `policy_rejected`，其他明确失败返回 `server_error`。
- 注入临时名称检查后被占用、写入失败、关闭失败、清理失败、rename 明确失败和响应丢失，验证最终状态与错误类型。
- 验证 `overwrite=true` 在有、无安全原子替换能力时分别提交或拒绝，且从不先删除旧目标。

## 回滚

如需改为严格的原子独占/no-replace 策略，或进一步放宽 `overwrite=true`，必须通过新的 ADR 重新评估服务器兼容性与数据完整性风险并取代本决定。实现阶段的代码回退按执行清单记录的 Start SHA 执行；已完成或结果不确定的远端写入不属于 Git 回滚范围。
