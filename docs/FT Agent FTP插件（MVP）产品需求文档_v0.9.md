# FT Agent FTP 插件（MVP）产品需求文档 v0.9

## 产品目标

通过本地 MCP stdio 服务，让 Codex 和 WorkBuddy 在用户配置的 FTP/SFTP 权限范围内发现服务器、浏览、读取、传输和维护文件，同时避免把凭据、连接元数据和真实服务器 root 暴露给模型。

## 核心需求

1. 提供 14 个职责明确的 MCP 工具，机器契约以运行时生成的 `docs/schema/mcp-tools.json` 为准。
2. 使用配置 v2：root 必填、默认只读、可选 description；不迁移旧版本。
3. Agent 只使用虚拟绝对路径；虚拟 `/` 映射到真实 root。
4. SFTP 主机密钥必须在用户认证前校验并安全持久化 TOFU 状态。
5. SFTP、FTP 可识别链接和本地上传链接均按 Accepted Spec 拒绝或跳过。
6. 上传按单文件限制，并通过同目录临时对象提交；写操作结果无法确认时不自动重放。
7. 下载校验已知大小，失败时清理本次产生的部分文件。
8. 批量工具逐项报告稳定的跳过、失败与不确定结果，不设置客户端批次总量限制。
9. 业务错误在线级返回 `isError=true` 和封闭结构；不得返回底层异常、凭据或连接信息。

## 验收

验收项目和安全边界以 `docs/spec/changes/next-development.md` 第 17 节 A01-A44 映射为准。实现必须通过 pytest、ruff、mypy、Schema 重建、授权 FTP/SFTP live 测试及 Codex/WorkBuddy 真实宿主验证。服务端负责正确发送 MCP annotations，并至少在一个真实宿主完成模型侧端到端验证；第三方宿主是否消费或向模型透传 annotations 不属于服务端保证。两个正式宿主都必须正确提供结构化错误并处理批量不确定结果；任一强制宿主能力失败时阻塞交付。

## 非目标

本轮不包括 FTPS、发布流程改变、配置迁移兼容、本地允许根白名单、批量配额、远程哈希协议扩展或自动回滚远端写入。
