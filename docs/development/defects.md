- 当前已经实现的行为与已知契约缺口，以 `docs/spec/current.md` 为准。

- 不改变公共契约的内部修复，可以直接关联本台账、代码提交和回归测试。
- 版本发布后，在 `RELEASE-NOTES.md` 记录用户可观察的修复结果。
- 接入正式 Issue 系统后，以 Issue 为状态来源；本文件保留迁移映射，不再双向维护状态。

## 4. 缺陷详情

### BUG-001：`upload_file` 未执行单文件大小限制

- **优先级**：P1
- **状态**：Fixed
- **影响范围**：`upload_file`、配置字段 `max_file_size_bytes`、工具说明与测试
- **当前行为**：`download_file`、`download_dir` 和 `upload_dir` 会使用 `max_file_size_bytes`；`upload_file` 只校验本地路径和目标覆盖策略，不校验文件大小。
- **风险**：用户可能认为该服务器级限制覆盖所有上传文件，但 `upload_file` 可以绕过限制，造成超预期传输或资源占用。
- **已确认目标**：`max_file_size_bytes` 仅约束上传，并对 `upload_file` 与 `upload_dir` 中每个普通文件表达同一含义；默认 2 GiB，允许 `0` 表示不限制。`upload_file` 在连接前预检并在传输中累计实际字节；`upload_dir` 不预扫描完整目录，逐文件流式检查，超限项安全清理后记入 `skipped` 并继续。
- **验收要点**：覆盖默认值、`0`、负数和 boolean、边界值、连接前拒绝、预检后文件增长、批量部分/全部超限、同目录唯一临时对象、安全提交、临时文件清理以及最终目标未被超限传输改变。
- **第三方证据**：`ftp-mcp-server测试报告-v0.2.2-20260915-v3.doc` 的 P-10 在 SFTP 场景复现了“下载受限、单文件上传不受限”的不一致行为。
- **关联 Spec**：`docs/spec/changes/next-development.md` 第 12、13、17 节；关联 ADR：`docs/decisions/0003-per-file-upload-limit-without-batch-limits.md`、`docs/decisions/0007-snapshot-authorized-upload-commit.md`。

### BUG-002：非幂等写操作自动重试前缺少结果核验

- **优先级**：P1
- **状态**：Fixed
- **影响范围**：service 重试策略、上传、重命名、移动、删除及错误契约
- **当前行为**：`server_error` 和 `connection_unavailable` 会自动重试一次。若服务器已经完成写操作，但响应在返回途中丢失，客户端无法区分“未执行”和“已执行”，直接重放可能得到目标已存在、源不存在等二次错误，或产生重复副作用。
- **已确认目标**：保留自动恢复能力，但连接异常后不得直接重放写操作。必须先重新连接并核验操作后的实际状态，再决定返回成功、执行一次重试或返回“结果不确定”。
- **结果核验原则**：
  - 只有身份或内容证据达到变更 Spec 的成功判据时，才将操作视为已经成功；仅凭删除后目标不存在，或移动后源不存在且目标存在，均不足以排除并发变化或目标替换。
  - delete 请求发出后发生连接异常或响应丢失时一律返回 `outcome_unknown`；FTP `unique` 只能辅助识别操作前对象或后续替换，不能证明本调用导致删除。
  - 预期结果明确未发生时，允许执行一次原操作重试。
  - 状态检查本身失败或无法可靠判断时，不得盲目重放；返回可识别的“结果不确定”状态及人工核验指引。
- **上传操作约束**：若无法取得可信的远端大小或内容哈希，就不能证明第一次上传完整，也不能把第二次上传自动升级为覆盖操作。无论原调用的 `overwrite` 为何，此时都不得直接再次上传。
- **临时路径边界**：变更 Spec 已接受使用临时路径避免超限或失败上传暴露为最终目标，但临时路径加 rename 不能作为响应丢失后的身份或成功证据，也不改变 `outcome_unknown` 判定。
- **验收要点**：模拟“服务端已完成但客户端收到连接异常”，分别覆盖上传、移动、重命名和删除；证明系统总是先核验状态，明确未执行时才重试，上传结果无法确认时不会自动覆盖或重放。
- **关联 Spec**：`docs/spec/changes/next-development.md` 第 14、15、17 节；关联 ADR：`docs/decisions/0007-snapshot-authorized-upload-commit.md`。

### BUG-003：FTP `NLST` 回退时批次总大小预检不完整

- **优先级**：P1
- **状态**：Won't Fix
- **影响范围**：FTP driver、`download_dir`、批量限制和错误语义
- **当前行为**：FTP 目录枚举按 `MLSD -> LIST -> NLST` 回退。部分服务器只支持或最终回退到 `NLST`；该命令通常只返回名称，无法提供可靠文件大小。当前未知大小按 0 参与批次总大小预检，因此 `max_batch_total_bytes` 可能无法提前阻止超限下载。
- **风险**：取消客户端下载大小与批次总量限制后，下载可能占用超预期带宽、本机磁盘和执行时间；未知大小不会再违反一个对外承诺的客户端上限，但资源风险仍然存在。
- **不修复决定**：本轮取消上传和下载的批次总字节限制，并取消全部下载文件大小限制，不再为 FTP `NLST` 设计未知大小预检或流式中止方案。因此本缺陷描述的“绕过客户端下载总量限制”不再适用。
- **风险接受**：用户于 2026-09-21 明确接受无客户端下载大小和批次总量限制的资源风险；服务端配额和限制仍可独立拒绝操作。
- **关联 Spec**：`docs/spec/changes/next-development.md` 第 12、19 节；关联 ADR：`docs/decisions/0003-per-file-upload-limit-without-batch-limits.md`。

### BUG-004：超长无换行文本预览返回空内容

- **优先级**：P2
- **状态**：Fixed
- **影响范围**：`read_text_preview` 返回内容、完整性元数据和工具说明
- **当前行为**：文件超过预览上限且截取范围内没有换行符时，为保证“只返回完整行”，当前返回空字符串。调用方可能误认为文件为空。
- **已确认目标**：返回预览上限内的部分行内容，并明确标记该内容是不完整行；保持 `truncated=true`，不得将部分行表示为完整预览。
- **错误语义说明**：不采用“明确错误”方案。“明确错误”原指在无法返回完整行时返回结构化策略错误，要求调用方改用下载工具；本项目已选择返回部分行，因此不应把该场景作为失败。
- **已确认字段语义**：返回部分行时固定使用 `partial_line=true`；`returned_lines` 计入已返回的部分行。发生截断时 `total_lines=null`，未截断时返回准确总行数；成功结果不再返回 `hint`。
- **验收要点**：覆盖 UTF-8、UTF-8 BOM、GBK、多字节字符边界、超长首行、首字符超过预算、无尾换行、正常多行文本，以及 `returned_lines`、`total_lines`、`partial_line` 和 `truncated` 的组合语义。
- **关联 Spec**：`docs/spec/changes/next-development.md` 第 11.4、11.7、17 节；关联执行清单：A25。

### BUG-006：setup 跨字段校验时机和安全默认值提示不完整

- **优先级**：P2
- **状态**：Fixed
- **影响范围**：setup 向导、配置默认值、root/readOnly/description 配置契约及相关文档
- **当前行为**：基础类型会在单字段输入时校验，但 root、协议专属字段等语义校验主要在全部字段收集完成后执行；`readOnly` 当前缺省为 false，root 允许留空，提示不足以表达其安全影响。
- **风险**：用户可能在输入完凭据后才发现较早字段无效，也可能在不了解影响的情况下建立无 root 限制或默认可写的服务器配置。
- **已确认目标**：配合下一功能批次的新配置契约，setup 应准确展示 `readOnly=true` 的安全默认值、必填 root 和可选 description，并在离开相关字段或字段组时尽早完成可确定的校验。
- **验收要点**：覆盖默认值展示、root 即时校验、FTP/SFTP 专属字段校验、返回上一步、取消和配置不落盘。
- **第三方证据**：`ftp-mcp-server测试报告-v0.2.2-20260915-v3.doc` 的 P-02。
- **关联 Spec**：下一轮 MCP 契约、安全边界与服务器发现变更 Spec。

### BUG-008：`read_text_preview.max_bytes` 超限时静默钳制

- **优先级**：P2
- **状态**：Fixed
- **影响范围**：`read_text_preview` 输入 Schema、运行时校验、错误契约和工具说明
- **当前行为**：`max_bytes` 大于 1048576 时被静默钳制为 1 MiB；调用方无法从结果确定请求值未被完整采用。
- **风险**：Agent 可能误认为服务按请求范围读取，并基于不完整内容作出判断。
- **已确认目标**：inputSchema 保留整数类型并在 description 中说明 `1 <= max_bytes <= 1048576`，不设置会触发 FastMCP 调用前拒绝的范围关键字；范围由工具运行时校验，超出范围时不执行远端读取，以 `isError=true` 返回统一结构化参数错误，不再静默钳制。
- **验收要点**：覆盖 0、负数、布尔值、边界值、超上限值，以及超限时未建立远端读取操作。
- **第三方证据**：`ftp-mcp-server测试报告-v0.2.2-20260915-v3.doc` 的 P-09。
- **关联 Spec**：下一轮 MCP 契约、安全边界与服务器发现变更 Spec。

### BUG-009：FTP 与 SFTP 的 `mtime` 返回格式不一致

- **优先级**：P2
- **状态**：Fixed
- **影响范围**：FTP driver、目录项和文件信息输出 Schema
- **当前行为**：FTP 的 MLSD `modify` 值可能直接以 `YYYYMMDDhhmmss[.sss]` 返回，SFTP 则返回 ISO 8601 时间。
- **风险**：调用方必须理解协议差异，排序、比较和展示可能产生不一致结果。
- **已确认目标**：所有公开 `mtime` 统一为 ISO 8601；能够确定时使用 UTC 并带时区。无法可靠解析时返回 null，而不是暴露协议原始格式。
- **诊断边界**：协议原始时间只允许进入受保护诊断日志，不作为 MCP 工具结果字段返回。
- **验收要点**：覆盖 FTP MLSD 秒、带小数秒、LIST 回退、MDTM、缺失或非法时间，以及 SFTP 回归测试。
- **第三方证据**：`ftp-mcp-server测试报告-v0.2.2-20260915-v3.doc` 的 P-11。
- **关联 Spec**：下一轮 MCP 契约、安全边界与服务器发现变更 Spec。

### BUG-010：批量限制错误缺少结构化限制上下文

- **优先级**：P3
- **状态**：Won't Fix
- **影响范围**：`upload_dir`、`download_dir`、错误 Schema 和工具说明
- **当前行为**：批量超限主要通过自然语言 message/hint 返回，缺少稳定的限制种类、配置上限、实际值和是否开始执行等机器可读信息。
- **风险**：当前行为中的自然语言批量限制错误不利于机器判断，但该错误所对应的客户端文件数和批次总字节限制已从目标契约删除。
- **不修复决定**：不再实现文件数或批次总字节的工具级预检错误。`upload_file` 的逐文件超限继续使用结构化 `limit_details`；`upload_dir` 的逐项流式超限使用带结构化限制信息的 `skipped` 项，二者由新的上传文件限制契约覆盖。
- **风险接受**：用户于 2026-09-21 明确决定取消批次文件数和总字节限制，接受对应资源风险；原批量限制错误无需继续兼容。
- **第三方证据**：`ftp-mcp-server测试报告-v0.2.2-20260915-v3.doc` 的 P-13。
- **关联 Spec**：`docs/spec/changes/next-development.md` 第 11.7、12、14、19 节；关联 ADR：`docs/decisions/0003-per-file-upload-limit-without-batch-limits.md`。

### BUG-011：`upload_dir` 使用文件系统根目录时触发未初始化变量

- **优先级**：P2
- **状态**：Verified
- **影响范围**：`upload_dir` 的本地源路径预检与本地普通路径检查
- **修复前行为**：当 `local_path` 恰好是当前平台的文件系统根目录时，逐段检查循环没有执行，局部变量 `info` 未初始化；后续目录类型检查触发 `UnboundLocalError`，并向调用方返回 `server_error`。
- **风险**：合法的绝对根目录不能作为批量上传源，但失败发生在远端连接和文件读取之前，不会产生远端副作用或绕过路径安全边界。选择根目录下的具体子目录可以规避。
- **修复目标**：先对文件系统根路径自身执行 `lstat` 并初始化检查结果，再按既有规则逐段拒绝符号链接和重解析点、验证最终对象类型；不改变公开参数、结果结构或错误契约。

## 5. 第三方报告中不登记为缺陷的事项

- **P-01 安装提示过细**：作为安装体验 backlog 管理，不作为当前功能缺陷。
- **P-03 1000 文件被拆成多次上传**：多次调用来自上层 Agent 任务拆分，证明单次调用数量限制不能形成任务级资源边界。本轮已决定删除 `max_batch_files`，不将 Agent 分批或重复调用登记为产品缺陷；资源治理如需恢复，应另行设计任务级配额、并发或速率限制。
- **P-04 批量下载/目录下载语义不清**：作为本轮工具描述和契约澄清处理，不单独登记实现缺陷。
